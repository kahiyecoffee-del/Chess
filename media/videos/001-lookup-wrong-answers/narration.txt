## A price for a product that doesn't exist
This lookup says product ten oh four costs forty-nine dollars. Product ten oh four doesn't exist. It was discontinued and deleted from the price list. There's no error and no warning. Just a believable number that's wrong. Lookups fail like this all the time, and the dangerous failures are the quiet ones. Here are four of them, why each one happens, and the one-line fix. By the end, you'll know exactly when V-lookup lies, when X-lookup still can, and a thirty-second check you can run on any report. The practice file is linked in the description, so you can break these formulas yourself.

## 1. Approximate match is the default
Look at the formula. It has three arguments. The fourth one, range lookup, is missing. When you leave it out, V-lookup doesn't do an exact match. It does an approximate match. Approximate match assumes the first column is sorted, and returns the largest value that is less than or equal to what you asked for. We asked for ten oh four. The largest ID that isn't bigger than ten oh four is ten oh three. So you get the laptop stand's price. Ask for ten twelve, an ID past the end of the list, and you get the last row's price. Still no error. And if the column isn't sorted at all, the result is unreliable. The fix is one word: FALSE. Add it as the fourth argument. Now a missing product gives you the N-A error, which is exactly what you want. An error is a warning. A wrong number is a trap. X-lookup flips the default. It does an exact match unless you ask for something else. If your version of Excel has it, that alone is a good reason to switch.

## 2. The column that moved
This formula was written when column three was the price. Then someone inserted a category column. V-lookup's column number is just a typed number. Excel doesn't change it when the table changes. So column three is now the product name, and our price column shows text. If the new column had been numbers, you'd get a different number instead, and that's when nobody notices. X-lookup doesn't count columns. You point at the lookup column and the return column directly. Because those are real references, inserting columns doesn't break it. If you're stuck with V-lookup, replace the typed number with a MATCH on the header row. That version is in the practice file too.

## 3. Duplicates return the first match
Which plan is ACME on today? The formula says Basic. But ACME appears three times. Both V-lookup and X-lookup return the first match they find, searching from the top. Our rows are in date order, so the first match is the oldest record. X-lookup has a search mode argument. Minus one searches from the last row upward, so you get the most recent record. This only works if the data is sorted by date. If it isn't, sort it first, or pick the row with the latest date. That's coming in a separate video.

## 4. Numbers stored as text
The last one is the sneakiest. These IDs came from a CSV export, and the total says fifty-four dollars. Looks fine. But the middle row returned zero. Look at the ID. It's aligned to the left. Excel aligns numbers to the right and text to the left, so this ID is text. And it has a trailing space. To Excel, the number ten oh four and the text ten oh four with a space are different values, so the exact match fails. Normally that gives you the N-A error. But this formula is wrapped in if-error with a zero. So the error became a zero, and the zero disappeared into the total. The fix: TRIM removes the extra space, and the double minus turns the text into a number. Now the total is eighty-three dollars. And the lesson: don't use if-error to turn errors into zeros in anything that gets added up. Show a clear message like not found instead.

## The 30-second lookup check
Before you trust any lookup column, run this check. One. Does every V-lookup end in FALSE? Two. Is the column number typed by hand? Three. Can the key appear more than once? Count-if on the key column will tell you. Four. Are the keys numbers on both sides? Is-text will tell you.
